# air188 deployment

Air188 runs two LASA 1.3.1 Docker supervisors. The system `lasa-layer2-https.service` proxy serves both HTTPS endpoints.

| Backend | HTTPS API | Container | Loopback port |
|---|---|---|---|
| Primary | `https://192.168.0.188/lasa/v1` | `lasa-primary-131` | 8878 |
| Review | `https://192.168.0.188/review/lasa/v1` | `lasa-review-131` | 8879 |

Use `yang@192.168.0.188` for administrative SSH. The Mac parent delegates over authenticated HTTPS with a separate receiver-scoped token for each backend.

On air188, the role directories are under `/home/yang/Dev/CodeX/LASA/v0/.deploy/target/docker-1.2.0`. The `primary` and `review` roles each use `deployment-1.3.1/config.json` and the separate receiver policy under `deployment-1.3.0/authorization.json`. Each container uses its role's persistent `private` and `workspaces` directories. The previous 1.3.0 containers are available for rollback.

The [managed deployment report](DEPLOYMENT.md) records the rollout order, readiness checks, and evidence that the primary backend consumed the review backend's exact output. The same report preserves the earlier systemd deployment record.
