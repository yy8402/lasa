# air188 deployment

Air188 runs both backends on LASA 1.6.0 with protocol `lasa/1.2`, v3 manifests, and deployment revision `docker-1.6.0-v3-34fe28cf1d36`. The system `lasa-layer2-https.service` proxy serves both HTTPS endpoints using `/etc/lasa/layer2.Caddyfile` and the installed backend CA at `/etc/lasa/docker-1.2.0-ca.pem`.

| Backend | HTTPS API | Container | Loopback port | Authentication |
|---|---|---|---|---|
| Primary | `https://192.168.0.188/lasa/v1` | `lasa-primary-160` | 8878 | JWT |
| Review | `https://192.168.0.188/review/lasa/v1` | `lasa-review-160` | 8879 | Static token with a workload identity pin for delegation |

Use `yang@192.168.0.188` for administrative SSH. The Mac parent delegates to each backend over authenticated HTTPS using its separately configured peer credential.

## Directory layout

The v3 rollout moved configuration and service state to stable paths under `/home/yang`. Each role bind-mounts its state root at the same absolute path inside its supervisor. Its manifest and policy use a separate read-only config mount.

```text
~/.config/lasa/
  primary/
    config.json
    authorization.json
  review/
    config.json
    authorization.json
  secrets/
    primary/
    review/
  registries/review/
    static-tokens.json
    static-tokens.json.lock

~/.local/state/lasa/
  primary/
    private/
    workspaces/
  review/
    private/
    workspaces/
```

Primary's JWT JWKS and each service's model and TLS files remain in their role-specific directories under `~/.config/lasa/secrets/`. Primary's live document connector still uses `v0/.deploy/target/connectors/` and `v0/.deploy/target/documents/` in the checkout. The state move preserved 12 primary task records and 49 workspace entries, plus 13 review task records and 52 workspace entries.

## Legacy task archive

The archive on air188 is `/home/yang/.local/state/lasa/archives/air188-legacy-20261123/legacy-task-data.tar.gz`. It contains the former `.deploy/layer2/` and `.deploy/target/layer2/` trees with their task stores and workspaces, plus `.deploy/target/backups/`. The retired `lasa-layer2.service` user unit is inside the archive at `target/backups/lasa-layer2.retired-20261123.service`.

The cleanup verified SQLite integrity on restored copies of the prototype store, the former target store, and the database snapshot. These contained 12, 23, and 11 task records respectively. Verify the archive checksum on air188 with the adjacent `SHA256SUMS` file.

```sh
cd "$HOME/.local/state/lasa/archives/air188-legacy-20261123"
sha256sum --check SHA256SUMS
```

## Retained rollback releases

The 1.5.2 containers `lasa-primary-152` and `lasa-review-152` and the 1.5.1 containers `lasa-primary-151` and `lasa-review-151` are retained with their images and v2 manifests. They are stopped with restart policy `no`. The 1.6.0 containers run with `unless-stopped`.

The old role directories under `v0/.deploy/target/docker-1.2.0/` retain the rollback manifests and policies. Their old state, credential, and registry paths link to the corresponding stable locations. Both 1.6.0 configs and all four rollback configs passed `lasa config check` after the move. Stop the current container before starting a rollback container for the same role. [Managed rollback procedure](DEPLOYMENT.md#release-upgrades-and-rollback)
