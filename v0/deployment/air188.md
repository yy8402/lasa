# air188 deployment

Air188 runs two LASA 1.5.0 Docker supervisors. The system `lasa-layer2-https.service` proxy serves both HTTPS endpoints.

| Backend | HTTPS API | Container | Loopback port | Authentication |
|---|---|---|---|---|
| Primary | `https://192.168.0.188/lasa/v1` | `lasa-primary-150` | 8878 | JWT |
| Review | `https://192.168.0.188/review/lasa/v1` | `lasa-review-150` | 8879 | Static token with a workload identity pin for delegation |

Use `yang@192.168.0.188` for administrative SSH. The Mac parent delegates to each backend over authenticated HTTPS using its separately configured peer credential.

The role directories are under `/home/yang/Dev/CodeX/LASA/v0/.deploy/target/docker-1.2.0`. Each role uses `deployment-1.5.0/config.json`, the separate receiver policy under `deployment-1.3.0/authorization.json`, and its persistent `private` and `workspaces` directories. The review registry is `review/deployment-1.5.0/static-tokens.json`. The previous 1.4.0 containers are available for rollback.

The [managed deployment report](DEPLOYMENT.md) records the rollout order and the successful dependent workflow. For issuing and rotating static workload tokens, see the [mixed-auth configuration instructions](../RUNNING.md#mixed-authentication-for-delegation).
